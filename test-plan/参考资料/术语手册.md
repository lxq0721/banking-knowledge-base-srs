# 术语手册

> 配套《银行知识库测试方案》阅读用。D.1~D.4 为通用与本项目术语，D.5 为技术方案 V1.0 专有术语；每条给出白话解释与**本项目中的具体例子**。

> 本文件是理解辅助材料，**不构成验收依据**；术语口径与需求书表 1-2 冲突时，以需求书为准。

> 本附录用于对齐各方理解。D.1~D.4 为通用与本项目术语，D.5 为技术方案 V1.0 专有术语。每条给出白话解释与**本项目中的具体例子**，便于评审时逐条讨论。

### D.1 知识资产与治理类

| 术语 | 白话解释 | 在本项目的例子 |
|---|---|---|
| 台账 | 逐项目、逐知识维度的**打勾表**（不是文件清单）；项目一多，它是唯一能回答"哪些项目能建库、哪些是空壳"的东西 | 例：XX 子系统一张表，10 个知识维度分别标"程序齐全 / COPYBOOK 部分 / 业务流程缺失 / 权限模型不可得"，由此判定该项目为 B 档 |
| 知识维度清单 | 该沉淀的**知识分类**（而非文件格式分类），共 10 类 | 程序与结构 / 数据模型 / 交易与功能清单 / 批处理作业流 / 接口与报文 / 外部依赖 / 异常处理 / 业务规则 / 环境与配置 / 权限模型 |
| 账实一致 | 台账（或覆盖率报表）上写的与库里实际的**对得上** | 例：报表写"程序齐全"，实际库里少了 3 个成员 → 管理缺陷 |
| 反推 | 从现有代码**倒推**出缺失的文档类知识（开发侧工作） | 例：没有设计文档，通过读程序调用关系画调用图、读 COPYBOOK 整理字段含义成数据框架表 |
| 事实基准 | 判定答案对错时**以谁为准** | 例：代码写 `PIC S9(13)V99`，流程图写 `9(13)` → 以代码为准 |
| 解释参考 | 只能作辅助说明、**不能推翻**事实基准的材料 | 例：`llm` 生成的功能说明，用于帮助理解，不作为判定依据 |
| 来源类型 | 这条知识**是谁、怎么产出的** | 例：代码直出 / 文档原文 / 模型生成 / 人工修正（需求书表 7-5 的五级即由此细分而来；技术方案的 `source` = parser / llm / human 是实现字段） |
| 来源级别 | 不同来源的知识**能用来干什么** | 例：表 7-5 五级——L1a 直接作口径依据；L1b 注出处；L2 可作迁移口径；L3 作口径类结论须同时给出处；L4 仅供参照、不得作唯一依据 |
| 级别 / 状态（两个维度） | 级别由核验定、状态由人定，**不能混成一个字段** | 例：级别 L1a~L4；状态 可取用 / 已修正 / 有争议 / 已废止。一条 L4 内容可以"可取用"，一条 L2 也可以"已废止" |
| 确认闭环 | 生成 → 自动核验 → 人工确认 / 驳回 → 回流入库 | 例：20 条生成的业务规则交专家审核，15 条确认入库、5 条驳回并注明原因 |
| 基线版本冻结 | 测试期间把库内资料与源码快照**固定在一个版本**上 | 例：开发 10/20 又补了一批注释，测试锁定"2026-10-20 基线"跑完再换版 |
| 观察项 | 记录在案、但**不判缺陷**的问题 | 例：原始资料与 `llm` 生成流程图冲突 → 记观察项，转开发确认 |
| 分级准出 | 按资料完备度**分档**设定不同达标线 | 例：C 档（几乎无原始资料）不考核命中率，只考核"不冒充迁移依据、越权 100% 拦截" |
| 责任边界 | 谁负责哪一块，避免后期**互相甩锅** | 例：知识完整性归开发侧，测试只验证与报告 |

### D.2 检索与大模型类

| 术语 | 白话解释 | 在本项目的例子 |
|---|---|---|
| 切片 / chunk | 把长文档切成**小段**分别存储 | 例：一个 800 行的 COBOL 成员被切成 12 段，每段独立入库 |
| 嵌入 / 向量化 | 把文本转成数字向量存起来，靠"语义距离"找相近内容 | 例：中文提问"余额字段"能匹配到英文 `ACCT-BAL` 的定义段 |
| context（上下文） | 实际**送给大模型**、让它据此作答的那几段原文 | 例：用户问"余额字段怎么定义"，系统召回 5 段原文送进模型 |
| 原始候选 context / 最终送入 context | 前者是召回到的**全部**候选（含图扩展结果），后者是过滤裁剪后**真正发给模型**的部分 | 例：召回 10 段 + 图扩展 3 个实体，裁剪后只送 3 段 |
| 灰盒验证 | 既看界面结果，也能看到**内部中间产物**（切片、召回列表、图查询结果） | 例：用 Neo4j 只读账号导出切片，或调 API 取回 context |
| 溯源 / 出处定位 | 答案能不能**指回具体资料和位置** | 例：输出"见 ACCTMAS.CPY / 余额字段定义段 / 第 120 行"或 `[CBACT04C.cbl:462-466]` |
| 召回率 | 该找到的内容里，**有多少被找到了** | 例：应有 100 段相关切片，实际召回 85 段 → 85% |
| 检索命中率（Recall@5） | 期望资料有没有出现在**前 5 条**结果里 | 例：10 道题的期望来源有 9 道进了前 5 → 90% |
| 精确率 | 召回来的内容里**有多少是真正相关的** | 例：召回 10 条，其中 4 条无关 → 60% |
| 首位命中率 | 期望资料**排在第 1 位**的比例 | 例：衡量排序质量，比"命中前 5"更严格 |
| top-k | 一次最多召回**多少条** | 例：top-k = 5 表示只取最相似的 5 段（技术方案未定义取值） |
| 重排（rerank） | 召回后**用更强的模型重新排一次序** | 例：先召回 20 条，重排后取前 5 条送入模型（技术方案未提及是否使用） |
| token 截断 | 模型上下文有**长度上限**，超了要砍内容 | 例：召回 10 段但只塞得下 3 段，其余被丢弃 |
| 幻觉 | 模型**编造**库里没有的内容 | 例：库里没有该字段定义，模型照样答得像真的一样 |
| 隐藏幻觉 | 编造的答案**"看着是对的"**，但 context 里没有依据 | 例：答案正确，但查 context 发现是模型自己脑补的 → 必抓，属 P0/P1 |
| 越权 | **没权限的人拿到了不该看的内容** | 例：A 地区人员检索到了 B 地区资料 |
| 后置过滤 | 先检索出结果、**再**按权限删掉；风险是答案或引用片段已泄露 | 例：答案正文已含机密内容，只是引用列表被隐藏（技术方案为检索时过滤，非后置） |
| 串版本 | 提问现行版本，却召回了**旧版本**内容 | 例：大机同名成员多版本共存，答出的是已废止版本 |
| 标量属性过滤 | 检索时按"标签字段"过滤，而不是先取回再筛 | 例：只检索"已确认"的知识，或限定某个子系统（依赖 Neo4j 版本） |

### D.3 大机技术类

| 术语 | 白话解释 | 在本项目的例子 |
|---|---|---|
| 大机 / 主机 | 本项目核心系统跑在 IBM 大型机上 30 多年，**与 PC 服务器不是一套体系** | 例：资料形态、编码、工具链都与常见 Web 项目不同 |
| COBOL | 大机上最主要的业务语言，源码是**固定列格式**（不是自由缩进） | 例：换行、缩进都有规定列位 |
| 定宽格式 / 指示符列 / A 区 / B 区 | COBOL 的排版规则：1-6 列序号、第 7 列 `*` 注释 / `-` 续行；8-11 列 A 区、12-72 列 B 区 | 例：转成普通文本后缩进丢失，程序层级看不出来 |
| COPYBOOK / COPY | **公共字段定义文件**，被多个程序 `COPY` 进来复用 | 例：ACCTMAS.CPY 定义客户字段，被 20 个程序引用 |
| PIC 子句 | 字段的**格式定义**（长度、类型、存储方式） | 例：`PIC S9(13)V99 COMP-3` = 13 位整数 + 2 位小数、压缩十进制 |
| EBCDIC | 大机的字符编码，**与 PC 的 ASCII 不同** | 例：按 ASCII 读取大机文件会出现乱码 |
| JCL / PROC | 大机上**提交作业的脚本**与可复用过程定义 | 例：日终跑批的作业流程 |
| 批处理作业流 | 每晚定时跑的**一串作业及其依赖顺序** | 例：先清算、再总账，顺序错就数据错 |
| CICS / CSD | 大机**联机交易处理系统**与其资源定义 | 例：CSD 定义交易码与程序的对应关系 |
| BMS / MAP | CICS 的**绿屏终端界面定义** | 例：某交易对应的画面布局与字段 |
| DB2 / DDL | 大机上的**关系数据库**与建表语句 | 例：账户表建表脚本 |
| VSAM / KSDS / GDG | 大机的**文件系统 / 按键索引文件 / 分代数据集** | 例：GDG 分代文件若误关联，会答出旧一代数据 |
| XCTL / LINK | CICS 中把控制权转给另一程序 / 调用后返回 | 例：调用链分析依赖这两类关系 |
| SQLCODE | DB2 执行结果码，0 成功、+100 未找到 | 例：异常处理规则解读需要它 |
| RPG / CL / DDS | IBM i 平台上的程序、作业脚本、表与屏幕定义（**仅当平台含 IBMi 时适用**） | 例：若试点子系统在 IBM i 上，资料形态随之改变 |
| 非文本混入 | 编译产物、二进制、报表输出被**误当源码入库** | 例：需在入库环节识别并拦截 |

### D.4 测试执行与性能类

| 术语 | 白话解释 | 在本项目的例子 |
|---|---|---|
| 评测集 | 事先写好的**问题 + 期望答案 + 期望出处**清单，用来客观打分 | 例：50~100 条问题，按 9 类分类，含无答案题 |
| 准入 / 准出 | 开测前**必须满足**的条件 / 结束时**必须达到**的条件 | 例：准入含"能取回 context、基线已冻结"；准出含"越权拦截 100%" |
| P0~P3 | 缺陷等级：P0 致命、P1 严重、P2 一般、P3 轻微 | 例：未审核内容被召回属 P0；串版本作答属 P1 |
| TTFT（首字响应时间） | 流式输出中**从提问到出现第一个字**的时间 | 例：采集 TTFT 曲线看等待感 |
| 并发流数 | **同时进行**的对话（流）数量 | 例：压测同时开 50 条流式问答 |
| P95 | 95% 的请求在此数值以内，比平均值更能反映真实体验 | 例：TTFT P95 = 3 秒 |

### D.5 技术方案 V1.0 专有术语

| 术语 | 白话解释 | 在本项目的例子 |
|---|---|---|
| GraphRAG | **向量检索 + 图遍历结合**的检索增强生成方式 | 例：先向量找片段，再沿图扩展到关联实体，最后生成带出处的回答 |
| 语义类节点 / 边 | 图里表示"东西"和"关系"的两个基本元素 | 例：节点 = Program / Paragraph / BusinessRule / Subsystem / Copybook；边 = 调用、包含、描述 |
| Cypher | Neo4j 的**图查询语言** | 例：附录 C 的 RV-01 模板查"待审核队列" |
| 参数化 Cypher 模板 | 预写好的图查询语句，只允许传参、不允许改写结构 | 例：影响分析模板，防止注入与越权 |
| Neo4j | 本方案用的**图数据库**，同时承载向量索引、全文索引与图算法 | 例：`chunk_vec` 建立在 `(c:Chunk)` 上；节点数可放大到百万级 |
| 定位符 | 为每段内容生成的**稳定位置标识**，用于精确引用原文 | 例：问答可引用到"某文档第几页第几块" |
| evidence | 每条知识的**依据出处**，格式为"文件:行号"或文档定位符 | 例：`CBACT04C.cbl:462-466` |
| source / confidence / review_status | 知识的**产出方式 / 置信度 / 审核状态**三项属性 | 例：`source=llm`、`confidence=中`、`review_status=未审核` |
| CBMLens | 面向开发与架构师的**开源代码探索工具** | 例：用于查看程序、调用关系与知识文档 |
| MinerU / Docling / PaddleOCR | 三种**文档解析工具**（首选 / 备选 / 扫描件补充） | 例：PDF、Word、扫描件转成结构化 Markdown/JSON |
| MinIO | **对象存储**，存放源码快照、文档原件与知识文档 | 例：基线版本以源码快照为准 |
| 绞杀者模式 | **新系统逐步替换老系统功能、新老并存**的迁移模式 | 例：阶段 3 重构时的替换策略 |
| 等价性验证 / 回放比对 | 验证新老系统在相同输入下**输出一致** | 例：同一批交易回放，差异须为零或均已登记确认 |
| 阶段门禁 | 每个阶段能否进入下一阶段的**卡点条件** | 例：阶段 0 门禁＝"问答准确率与知识文档质量达到双方约定阈值" |
| POC | 概念验证阶段的**小范围实测** | 例：阶段 0 做模型对比、每千行代码耗时与压测数据 |
| 知识覆盖率 | 门户展示的**知识沉淀比例**视图 | 例：某子系统的知识与代码覆盖比例（本方案建议以"知识维度 × 子系统"打勾表落地） |
