# 评测集脚本执行包

配套《银行知识库评测集模板 v0.2》。xlsx 是给人填的，这里是给脚本跑的——表怎么排版、加不加列，都不影响跑批。

## 三步

```bash
# 1 导出（顺带校验，有错就别跑）
python export_jsonl.py ../银行知识库评测集模板_v0.2.xlsx
#    → eval_set.jsonl + 校验报告（缺必填、编号重复、要点拆不开、规则语法错）

# 2 跑批
python run_eval.py --endpoint http://<被测服务>/qa            # 打真实接口
python run_eval.py                                            # dry-run，不碰网络
python run_eval.py --endpoint ... --roles developer,ba,architect   # 权限题按角色各跑一遍
#    → results.csv（16 列，列名与 xlsx「执行记录」页一一对应，可直接粘贴）

# 3 回填
#    把 results.csv 按编号抄进「执行记录」页；判「待人工」的是待办，不是通过
```

自检（不依赖被测服务）：

```bash
python selftest_judge.py   # 11 条用例，覆盖判定器每个分支
python selftest_http.py    # 起假接口验 HTTP 通路，半数返 500 看硬失败判定
```

## 文件

| 文件 | 作用 |
|---|---|
| `export_jsonl.py` | xlsx → eval_set.jsonl，**按表头文字取列**，不按列号；改表不会读错 |
| `run_eval.py` | 读 jsonl、发问、判定、写 results.csv |
| `selftest_judge.py` | 判定器分支用例（11 条） |
| `selftest_http.py` | 假接口 + 子进程调 runner，验请求体与 5xx 处理 |
| `eval_set.jsonl` / `results.csv` | 中间产物，可删可重生成 |

## 判定顺序（改了会出错）

1. **硬失败优先**——5xx / 连接失败 / 超时 / 空响应 → 不通过，不看内容。先修可用性再看效果，否则 502 会被算进「答案不对」。
2. **无答案题专项**——`in_kb=否`：没说「未查询到」或给出了结论 → 不通过（幻觉，P0）。
3. **级别标注**——`expect_level` 属「模型生成·核验通过 / 未通过」的，回答里没有「模型生成 / 未核实 / 仅供参考」→ 不通过（标注缺失）。
4. **规则匹配**——`must` 全中、`must_not` 全不出现、`regex` 全命中 → 通过；命中一部分 → 部分通过；零命中 → 不通过。`must_not` 是否决项，不参与命中率分母。
5. **无规则 → 待人工**。没有判据就等于没判，不能当通过。

## 机器判定规则的写法

单元格里一条字符串，`|` 分隔：

| 写法 | 含义 |
|---|---|
| `ACCT-BAL` | 回答里必须出现（忽略大小写） |
| `!不支持` | 不得出现 |
| `/DD\s*[:：]/` | 按正则匹配 |

只写回答里会**原样出现**的硬事实：字段名、文件名、行号、级别词。写「余额 精度」这种中文说法，包含匹配永远落空，整批题会被误判成不通过。

## 字段映射（主表列 → JSON 键）

| 主表列 | JSON 键 | 说明 |
|---|---|---|
| 编号 | `id` | 唯一键，结果按它对回主表 |
| 所属范围 | `scope` / `subsystem` / `region` | 按「 / 」拆成两段 |
| 问题原文 | `question` | 第 6 类异常题可为空 |
| 问题类型 | `type` / `type_no` | 首字符即类号 |
| 需分角色执行 | `needs_role` | true 时按 `--roles` 展开成多行 |
| 库内是否存在该信息 | `in_kb` | 否 → 走幻觉专项 |
| 期望答案要点 | `points[]` | 按 ①②③ 切 |
| 期望出处 | `expect_sources[]` | 按分号切，用于算定位符准确率 |
| 机器判定规则 | `rules{must,must_not,regex}` | 解析后使用 |
| 备注 | `note` / `is_sample` | 含「示例」即 is_sample，跑批默认跳过 |

## 它判不了什么

- 答案是否「说清楚了」——要点都沾边但结论错，脚本照样判通过
- 冲突题处置是否合规（该并列的并列了没有、该记疑点的记了没有）
- 多轮题上下文是否绑对了对象
- 解释通道的表述是否越界（把推断说成事实）

这些必须留人工。报表里自动判定与人工抽检要分开列，不能合成一个「总分」——合了就没法解释「通过率 85% 是怎么算出来的」。

## 两个坑

**示例行**：xlsx 前 12 行是虚构占位数据，默认跳过。拿它们当真值跑出来的任何数字都无意义。

**超时不重试**：单条 60s 超时直接记不通过，不重试。重试会把长尾掩盖成「偶发」，而长尾恰恰是知识库最容易出问题的地方。
