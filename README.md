# 核心系统迁移知识库 · 需求规格书与测试资产

把存量 COBOL / CICS 资产转成可检索、可追溯、可核验的知识库——这个仓库是它的**需求规格书、测试方案与评测集**，一套从「要做什么」到「怎么验」的完整文档链。

主体按 **GB/T 9385**（计算机软件需求规格说明规范）编写：**138 条**功能与非功能需求、**485 条**验收标准、一套可点开的交互原型，以及每次改版的构建脚本。测试侧另有一套 10 章测试方案与 4 份可直接跑批的评测集。

> 本仓库为**去品牌版本**：不含委托方名称、真实交易码、生产数据与内网信息。文中出现的代码样例均来自公开开源项目（见[评测集语料](#评测集语料)）。

## 演进主线

项目走到 v3.18，不是线性堆需求，中间有两次转向。看懂这条主线，比逐版读改动要点更快：

| 阶段 | 版本 | 解决的核心问题 |
|---|---|---|
| 规范重构 | v1.5 – v2.0 | Demo 稿互相矛盾、结构松散；v2.0 按 GB/T 9385 重排全文，只动结构不动需求 |
| 定位升级 | v3.0 | 从「演示够用」改为「完整产品」，后续版本从全量里裁剪演示范围，而不是反过来补 |
| 能力补齐 | v3.1 – v3.4 | 按实际接入的资料类型补格式范围；补业务语义与经验累积；补全链路「人工在哪、自动在哪」 |
| 机制细化 | v3.5 – v3.7 | 把「是否调用模型」与「由谁触发」拆开；第 8 章入库建图从 3 张表扩到 6 张；切片口径从「规定切法」退为「参考口径」 |
| **定位转折** | v3.8 | 从「逐条人工审核」改为「辅助检索型」：核验不成立就降级不拦截，人工只守两道门（生成前定范围、上线前抽检） |
| 口径校正 | v3.9 – v3.12 | 可由代码推出的结构从「文档增强」移回「源码必出」；补资料齐备度矩阵；拆开业务术语的两类依据；补来源不一致的判定与疑点清单 |
| **收敛归并** | v3.13 – v3.18 | 按评审意见删冗余、把银行必备而非项目必备的 5 条移出正文；14 组同主题条目并为「一条判据 + 一张表」；v3.16 补回归并过程中漏掉的重算规则，v3.17 补经验沉淀缺的数据对象，v3.18 补资料失效后的知识层处置 |

两次转折值得单独说：

- **v3.8** 把「模型生成的都要人审」这个前提推翻了，改成按下游用途分档。否则 3000 个程序的知识量没有任何团队审得完——人工判定过多是定位错位，不是条目写错。
- **v3.13–v3.18** 反过来的动作是**把已经写进去的东西删掉**。判断标准只有一条：这条需求要改，得同时改几处？改两处的必须合并——历次自相矛盾，全是同一规则写在了文档的两个地方。

## 编号与优先级约定

- 功能需求 `FR-<域>-两位`，域为 `IMP` 接入 / `PRS` 解析 / `GEN` 生成 / `REV` 核验 / `STO` 入库 / `GRP` 图谱 / `QA` 问答 / `DAT` 数据；非功能为 `NFR-两位`
- 编号与章节号解耦，删条**留空不复用**，新增接域尾
- 优先级只有三档：必须 / 应该 / 可选，**集中在 1.4 与附录 A 维护**，条目内只标注不解释
- AC 的唯一出处是验收清单 xlsx，正文条目只写编号、标题、优先级、约束、描述五段

## 评测集语料

评测集不自己造语料，题目与判分依据全部落在两个公开开源项目的真实代码行上：

| 语料 | 仓库 | 用途 |
|---|---|---|
| CardDemo | [aws-samples/aws-mainframe-modernization-carddemo](https://github.com/aws-samples/aws-mainframe-modernization-carddemo) | 主语料。42 个 COBOL 程序、62 个 copybook、55 个 JCL、21 个 BMS 屏幕、CSD 资源定义与 DDL/DBD |
| Z Open Editor 样例 | [IBM/zopeneditor-sample](https://github.com/IBM/zopeneditor-sample) | 首版语料。COBOL / PL/I / JCL / 混编，适合校验跨语言同名定义 |

100 题分五类：代码与结构事实、业务语义、行员真实提问、来源冲突识别、质量与边界。**判分依据里带文件名与行号**，可逐条回到源码核对。评测集字段、判分规则语法（`A|B|!C|/regex/`）、四步判定顺序见 [`eval-set/README.md`](eval-set/README.md)。

跑批链路：

```bash
# xlsx → JSONL（按表头文字取列，不依赖列序）
py -3 build/eval-set/runner/export_jsonl.py --xlsx eval-set/银行知识库评测集_CardDemo实测100题_v2.0.xlsx

# 判分自检（11 条用例，覆盖硬失败、幻觉、标注缺失、规则匹配、待人工）
py -3 build/eval-set/runner/selftest_judge.py

# 对被测接口跑批
py -3 build/eval-set/runner/run_eval.py --input eval-set/jsonl/eval_cd100.jsonl
```

## 改版流程

构建脚本是**增量补丁**，不是从零生成器：每个 `v3xx_stepN.py` 读取上一版正本、改一处、写出中间文件，链式跑到最后一版。

```bash
# 依次执行本版脚本（step1 读上一版 docx，step3 落最终文件）
py -3 build/v3.18/v318_step1.py
py -3 build/v3.18/v318_step3.py     # 更新域、清属性、落 release

# 导出 PDF（需本机装有 Word）
py -3 build/tools/export_pdf2.py <docx> <pdf>

# 改版后重算验收清单并导出
py -3 build/v3.18/v318_xlsx.py      # 改文本、按 AutoFit 修正行高并导出 PDF

# 附录 C 改动后重新生成 CHANGELOG
py -3 build/tools/gen_changelog.py
```

改版必查的连带项：表 1-3 与表 A-1 的条数、表 3-2 与表 B-1 的功能组编号（**两表列序不同**）、附录 B 统计、清单统计页。这些位置不随正文自动同步，是历次改版最容易漏的地方。

## 范围说明

本仓库只覆盖「要不要做、做到什么算成立」，不含技术选型参数（嵌入模型、向量维度、切片长度余量、相似度度量口径）。这些属技术方案，正文仅在需要帮助读者理解需求时保留参考口径，并声明不作为验收依据。

`guide/` 下的测试指南是配套的方法参考，不属于需求正文；两者冲突时以需求书与验收标准清单为准。
